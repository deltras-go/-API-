# TransferSimulator Client (Go)

Клиентское веб-приложение для API эмулятора **TransferSimulator** (Модуль 4,
«Осуществление интеграции программных модулей»). Приложение показывает
данные, которые возвращает API, и позволяет выбрать тип данных из
выпадающего списка (`fullName`, `snils`, `inn`, `email`, `identityCard`).

## Как это устроено

```
transfer-client/
├── main.go            # веб-сервер на Go: отдаёт страницу и ходит в API
├── static/index.html  # страница с выпадающим списком и кнопкой
├── mockserver/main.go # локальная заглушка API — для разработки без сети лаборатории
├── go.mod
└── README.md
```

Браузер обращается **не напрямую к TransferSimulator**, а к встроенному
Go-серверу (`/api/data?type=...`), а уже сервер сам делает GET-запрос к
реальному API и возвращает ответ странице как JSON.

Почему так, а не `fetch()` из JS напрямую в API: TransferSimulator не
отдаёт CORS-заголовки, поэтому прямой запрос из браузера на другой
хост/порт будет заблокирован политикой CORS. Запрос сервер-сервер этому
ограничению не подчиняется, поэтому вынесение похода в API на сторону Go
снимает проблему полностью.

## Запуск

Требуется Go 1.21+.

```bash
# по умолчанию используется адрес сервера лаборатории (НЕ localhost):
# http://192.168.1.200:4444/TransferSimulator
go run .
```

Приложение поднимется на `http://localhost:8080`. Откройте эту страницу в
браузере, выберите тип данных и нажмите «Получить данные».

### Настройка адреса API

Адрес API и порт самого клиента можно переопределить флагами или
переменными окружения (по умолчанию — адрес лаборатории, не localhost):

```bash
go run . -base-url http://192.168.1.200:4444/TransferSimulator -addr :8080

# то же самое через переменные окружения
TRANSFER_API_BASE_URL=http://192.168.1.200:4444/TransferSimulator APP_ADDR=:8080 go run .
```

### Локальная заглушка API (для разработки без сети лаборатории)

Реальный сервер (`192.168.1.200`) доступен только в кабинете. Чтобы
разрабатывать и проверять приложение в любом другом месте, в комплект
включена простая заглушка, отвечающая теми же примерами, что приведены в
`api_info.docx`:

```bash
# в одном терминале
go run ./mockserver

# в другом терминале
go run . -base-url http://localhost:4444/TransferSimulator
```

**Это не замена реальному тестированию** — перед сдачей обязательно
проверьте работу именно с `http://192.168.1.200:4444/TransferSimulator` в
кабинете.

## Проверка API без кода — Bruno

Перед тем как писать/проверять код, работоспособность самого API стоит
проверить в Bruno:

1. Установить Bruno из `\\kab7-main\!Install_net\!programing\api\bruno_2.14.2_x64_win.zip`
   в `C:\Programs\API` (распаковать архив).
2. Создать новый запрос типа **GET** на, например,
   `http://192.168.1.200:4444/TransferSimulator/fullName`.
3. Отправить запрос и убедиться, что приходит `{"value": "..."}`.
4. Повторить для `snils`, `inn`, `email`, `identityCard`.
5. Если Bruno получает `500 Internal Server Error` — это, скорее всего,
   проблема на стороне сервера лаборатории; сразу сообщите главному
   эксперту, как указано в `api_info.docx`.

Только после того как запросы в Bruno отрабатывают штатно, переходите к
запуску `go run .` и проверке того же самого через приложение.

## Ручная проверка (без браузера)

```bash
curl "http://localhost:8080/api/data?type=inn"
# {"type":"inn","value":"7707083893%"}
```

## Публикация в Git

Ниже — минимальный набор команд, чтобы выложить проект в свой репозиторий
(например, на GitHub). Замените `<URL-вашего-репозитория>` на реальный
адрес пустого репозитория, который вы создали в веб-интерфейсе GitHub/
GitLab:

```bash
cd transfer-client
git init
git add .
git commit -m "Client for TransferSimulator API (Module 4)"
git branch -M main
git remote add origin <URL-вашего-репозитория>
git push -u origin main
```

После этого в качестве ответа на задание отправьте ссылку на репозиторий
(или, как допустимая альтернатива, приложите архив папки проекта).
